# Voice Bot

[English](README.md) | [Русский](README.ru.md)

Telegram-бот для голосовых сообщений.

- Расшифровывает голосовые сообщения, сохраняя полный текст в сворачиваемой цитате.
- Составляет краткий пересказ записей.
- Объединяет несколько пересланных голосовых в одну расшифровку и общий пересказ.

## Контекст и серии голосовых

Бот показывает «печатает…» во время обработки. На каждое третье голосовое
одного автора (3-е, 6-е, 9-е) приходит один ответ: «Коротко · 3 голосовых»
с итогом текущей тройки и полная сворачиваемая расшифровка текущей записи.
Отдельного сообщения с итогом нет. Первые две расшифровки приходят сразу. После первого и второго коротких голосовых
итога нет. Текстовые сообщения этого автора входят в контекст, но не в счётчик.
Итог на шестом голосовом охватывает записи 4–6; более ранние исходные сообщения
помогают понять отсылки, но не пересказываются заново.
Одиночная запись от 30 секунд сохраняет обычный пересказ; продолжение серии
суммируется на каждой третьей записи. Пересланные пачки работают отдельно.

Пауза между сообщениями автора больше 180 секунд начинает новую серию.
По умолчанию окно ограничено 15 минутами, 12 сообщениями и 12 000 символами
на автора, всего до 200 активных контекстов. При превышении лимитов старые
данные удаляются; полная расшифровка в Telegram не сокращается.
Ключ контекста включает ID чата, настоящей темы форума и автора. Обычные ответы
на сообщения остаются в серии автора: ID ветки ответов не считается темой форума. Имена не используются
как идентификаторы. Пересылки отделены от живой беседы; приватный `/text`
не читает и не пополняет публичную память. В тихом режиме текст не собирается.
Бот учитывает только полученные Telegram updates, историю чата не подгружает.

Контекст и отметки отправленных итогов восстанавливаются после перезапуска.
Один процесс бота должен владеть одним каталогом данных; между экземплярами
его не разделяют. Необработанные задания и прогресс доставки сохраняются в SQLite.
Запись снимка контекста атомарная, файл имеет права `0600`. Ошибка снимка отключает
общие итоги. Ошибка журнала очереди останавливает polling до подтверждения новых updates. Итог обрабатывается в той же очереди и доставляется тем же механизмом защиты
от повторов, что и обычная расшифровка. Если текст превышает лимит Telegram,
он разбивается на части с сохранением всей расшифровки.

Параметры — `CONTEXT_*` в [.env.example](.env.example).
`CONTEXT_SUMMARY_EVERY=0` отключает общие итоги, `CONTEXT_TTL_SECONDS=0` — весь
сбор контекста. При обновлении со старой версии увеличьте `CONTEXT_MAX_CHARS`
с 800 до 12000, если это значение уже было явно записано в `.env`.

## Контекст сообщения, на которое ответили

Если голосовое отправлено ответом на другое сообщение, сводка учитывает именно этот
источник: текст, подпись (в том числе у сообщений ботов), голосовое или речь из
круглого видео (`video_note`). У обычных видеороликов и других вложений используется
только текстовая подпись; само вложение для контекста не скачивается и не распознаётся. Реплика собеседника отделена от
слов автора. Reply у первого или второго голосового сохраняется до итога третьего,
в том числе после перезапуска. Он не увеличивает счётчик автора и не добавляется
в дословную расшифровку. Следующая тройка не наследует чужую реплику без нового reply.

Используется только явно указанное сообщение в том же чате. Источники из других чатов
и ephemeral-сообщения исключены; соседняя переписка собеседника не загружается.
Явная ссылка на другую тему форума может дать фон, но счётчики тем остаются раздельными.
Обычные ветки ответов не считаются темами форума.

Готовые расшифровки используются повторно. Если речь исходного голосового/кружка ещё
не распознана, бот получает её через существующий путь загрузки, FFmpeg и STT с теми же
лимитами размера и длительности, внутри текущей задачи. Дополнительный контекст ограничен
45 секундами и оставляет время на итог. Из кружка учитывается только речь, не изображение.
Недоступный или слишком большой источник не мешает отправить собственную расшифровку;
сводка не должна додумывать пропущенный контекст. Модели не менялись.

Текст источника ограничен 3000 символами на голосовое и 6000 на итог, а также общим
лимитом символов контекста. Ограниченный источник и связь reply сохраняются рядом
с контекстом; ожидающее задание хранит один неглубокий снимок источника без рекурсивной
истории ответов. Сводка различает исходный вопрос/предложение, ответ/уточнение автора
и реальный итог, без выдуманных решений, пустых разделов и слов-паразитов.

Инструкция сводки различает события, намерения и отношение: сам reply не означает
согласия, а нежелание не доказывает, что действие уже сделали или не сделали.
Однозначные отсылки раскрываются конкретными деталями; несвязанный фон не повторяется
как новое содержание. Текущие тексты автора могут содержать отдельные темы.
Проверки микрофона и счёт без содержания опускаются в сводке; расшифровки сохраняются полностью.

## Подсказки написания при расшифровке

`gpt-transcribe` получает до 16 слов-подсказок (всего до 320 символов) из явного reply,
подписи самой записи и трёх предыдущих сообщений того же автора, чата и темы форума
в пределах 180-секундного окна серии. Можно использовать уже готовые расшифровки;
повторное распознавание ради подсказок не выполняется. Написание из текстовых сообщений
имеет приоритет перед предыдущим STT. Используется только доступный текст: ещё не
распознанная запись из reply на этом этапе не скачивается. У обычных вложений берётся
только подпись.

Передаются отдельные слова с заглавными буквами, ограниченные по длине, без username,
URL, полных сообщений и разговорных инструкций. Используется отдельное поле `keywords[]`;
дополнительного переписывания расшифровки моделью нет. Текст ответа STT и его пробелы
сохраняются. Готовая расшифровка используется как есть; список подсказок сохраняется
в ожидающем задании, чтобы рестарт не менял его контекст. Приватный `/text` не читает
фоновую переписку. Отключение контекста отключает подсказки. Формат запросов других
настроенных моделей STT остаётся прежним.

Подсказки могут уменьшить ошибки написания, но не гарантируют безошибочное распознавание
или отсутствие выдуманных слов. В расшифровку должны попадать только произнесённые слова;
проверяются как нужные имена, так и посторонняя либо противоречащая подсказке речь.
Подпись автора в summary добавляется кодом бота: приоритет у имени,
`@username` используется только без имени.
Для пересылок сохраняется исходный автор.

## Постоянная очередь

Принятые голосовые, включая ещё собираемую пачку пересылок, переживают перезапуск.
Запись задания фиксируется до подтверждения Telegram update. Лимиты очереди,
порядок внутри чата и параллельная обработка разных чатов сохраняются.
Расшифровка и готовый summary сохраняются по завершении каждого этапа: при
восстановлении готовые результаты используются повторно без запросов к моделям.
Предыдущие голосовые для контекста summary не распознаются заново.

Каждая часть ответа отмечается перед отправкой; после подтверждения сразу сохраняется
ID Telegram. При восстановлении подтверждённые части пропускаются, в том числе
части длинных ответов и копии готовых расшифровок. Новый явный `/text` остаётся новым
приватным запросом; повторно полученный update новым запросом не считается.
Журнал использует SQLite из стандартной библиотеки, WAL, FULL synchronization и
блокировку одного процесса. Новых сервисов и зависимостей нет. `QUEUE_STATE_FILE`
по умолчанию — `data/queue.sqlite3`; Compose помещает его в постоянный volume.

**Граница гарантии:** у Telegram Bot API нет ключа идемпотентности отправки. Если
процесс или сеть прервались между отправкой и сохранением подтверждения, результат
неопределён. Задание сохраняется и **автоматически повторно не отправляется**.
Одновременно гарантировать отсутствие потерь и дублей в этом окне невозможно.
Это относится и к остановке непосредственно перед записью в сетевой сокет.

Посмотреть только ID и состояния, без текстов и аудио, можно на работающем боте:

```bash
docker compose exec voice-bot python -m voice_bot.queue_admin --path /app/data/queue.sqlite3 status
```

Для неопределённого задания сначала проверьте точный ответ в Telegram, остановите
бота и выберите один вариант сверки:

```bash
docker compose stop voice-bot
# Ответ подтверждён: укажите ID; 0 допустим только для проверенного ephemeral-ответа.
docker compose run --rm --no-deps voice-bot python -m voice_bot.queue_admin --path /app/data/queue.sqlite3 resolve JOB_ID --delivered-id REPLY_ID
# ИЛИ только после проверки, что ответ не был отправлен:
docker compose run --rm --no-deps voice-bot python -m voice_bot.queue_admin --path /app/data/queue.sqlite3 resolve JOB_ID --not-delivered
docker compose up -d --no-build
```

Не удаляйте журнал для очистки очереди. Резервную копию всего volume делайте при
остановленном боте. При обновлении с 0.3.0 нужна штатная остановка, чтобы прежняя
RAM-очередь успела завершиться: задания старой версии нельзя восстановить задним числом.

## Режимы работы в группе

| Режим | Поведение |
| --- | --- |
| Обычный (по умолчанию) | Автоматическая расшифровка голосовых для всей группы. |
| Тихий | Обработка только по `/text`; результат видит только отправитель команды. |

Администраторы группы выбирают режим кнопками в `/settings` или в приветствии бота.
Настройка отдельная для каждой группы и сохраняется после перезапуска.
Существующие группы продолжают работать в обычном режиме.
В обоих режимах требуется разрешение владельца бота на обработку в группе.

## Команды

| Команда | Действие |
| --- | --- |
| `/text` | Расшифровка голосового, на которое вы ответили; в группах ответ личный в обоих режимах. |
| `/settings` | Выбор режима группы; доступен администраторам группы. |
| `/start` | Справка и кнопки для добавления и настройки бота. |
| `/admin` | Разрешение или запрет обработки в группах; только для владельца бота в личке. |

Ответы на групповой `/text` — нативные **ephemeral-сообщения** Telegram, включая ошибки
и все части длинной расшифровки. При отказе приватной доставки бот не публикует результат.
`/text` и `/settings` зарегистрированы как скрытые групповые команды.
Чтобы скрыть саму команду, ответьте на голосовое и выберите приватную `/text` в меню
команд поддерживающего эту функцию клиента Telegram. Если в группе несколько ботов,
выберите команду именно этого бота (`/text@имя_бота`).

Публичные `/text` и `/settings` от старых клиентов или юзерботов удаляются через
5 секунд, если у бота есть право удаления сообщений. Исходное голосовое сохраняется.
В личке команды не удаляются; автоматическая обработка и дневные лимиты продолжают действовать.

Бот должен быть администратором группы. Ephemeral-сообщения временные и могут исчезать
при перезапуске Telegram; доставка офлайн-пользователю не гарантируется.
Команды `/text` и `/settings` от имени группы не обрабатываются. Подробнее — в [документации Telegram](https://core.telegram.org/bots/api#ephemeral-messages-and-commands).

## Развёртывание

Нужны Linux, Git, Docker Engine и Docker Compose v2. Входящие порты не используются.

```bash
git clone https://github.com/eugeneb1ack/telegram-voice-bot.git
cd telegram-voice-bot
test -e .env || cp .env.example .env
chmod 600 .env
```

Заполните в `.env`:

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather |
| `OPENAI_API_KEY` | Ключ OpenAI API |
| `OWNER_ID` | Telegram ID владельца |

Остальные настройки описаны в [.env.example](.env.example).

```bash
docker compose build
docker compose run --rm --no-deps voice-bot voice-bot --check
docker compose up -d
docker compose ps
```

Добавьте бота в группу и назначьте администратором. Затем с аккаунта, указанного
в `OWNER_ID`, отправьте боту `/admin` в личном чате и разрешите обработку для группы.

## Данные

Временные аудиофайлы удаляются после обработки. Ограниченные фрагменты исходных
расшифровок и обычного текста сохраняются в `conversations.json` в Docker volume
`group-state`, чтобы недавний контекст переживал перезапуски. Пока бот работает,
просроченные записи удаляются автоматически; после остановки — при следующем
запуске. Это не архив переписки. Остальные файлы volume хранят разрешения и режимы
групп, счётчики использования, хеши идентификаторов и ID публичных ответов.
Метаданные заданий, Telegram file ID, распознанный текст, готовый summary и прогресс
отправки временно хранятся в `queue.sqlite3` с правами `0600`. Аудио туда не записывается.
После завершения содержимое задания удаляется; остаются ограниченные по числу хеши
запросов. Неопределённые доставки сохраняются до явной сверки.
Служебные логи содержат стадии и длительности запросов без аудио, текстов,
ответов API, ключей и содержимого исключений Telegram.
Аудио, текст и контекст передаются в OpenAI для обработки; ответы остаются в Telegram.
